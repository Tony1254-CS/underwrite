01 · Executive brief

The control problem is authority, not intelligence

An AI agent can parse invoices and plan payments, but it should not be allowed to choose its own payee, token, calldata, or spending limit. UNDERWRITE places deterministic and on-chain controls between model output and money movement.

Distinctive contribution. UNDERWRITE mechanically couples per-configuration evidence to on-chain authority and collateral-backed exposure. The model proposes; deterministic software decides; the contract enforces.

Current demonstrated outcome

A real Base Sepolia qualification for the gamma configuration honestly produced zero Tier-1 authority under the utility gate, preserved bounded Tier-2 capability, and executed a controlled 35 MockUSDC delayed payment with a successful receipt and matching decoded event.

02 · User and job

Autonomous accounts payable, with a financial boundary

The target user is a treasury or accounts-payable owner already operating with stablecoins. The repeated job is to turn trusted business records into timely supplier payments without making a language model a custodian.

Agent workload

  • Read an inbox and extract invoice facts.
  • Resolve a vendor ID against a trusted registry.
  • Match purchase order and amount.
  • Detect duplicates and suspicious variants.
  • Propose or request a payment.

The non-negotiable boundary

The LLM never chooses an address, token, calldata, or limit.

Agent tools accept business identifiers such as vendorId. Trusted code resolves addresses and constructs transactions. Invalid, unknown, inconsistent, or out-of-envelope proposals cannot become arbitrary calls.

04 · Trust boundaries

Assume the model will fail

Untrusted zone

Model and external content

  • Invoice text and email content
  • Prompt injection and social-engineering payloads
  • Hallucinated entities or amounts
  • Provider availability and behavioral drift
Deterministic zone

Policy and chain controls

  • Vendor ID → trusted registry lookup
  • PO, amount and invoice-key validation

06 · Adversarial examination

Evaluate the exact configuration before granting authority

The unit under test is not an abstract model name. It is a canonical manifest of agent implementation, model/provider settings, prompt/tool/policy versions and corpus version, producing a configuration hash.

ManifestExact configuration
→
PrecommitConfig + corpus hashes
→
RunBenign + adversarial families
→
ScoreClass I / Class II
→
ReportCanonical evidence

Class I — control violation

An action that violates a deterministic business or authorization rule, such as wrong recipient, duplicate invoice, invalid PO relationship, or execution outside permitted conditions.

Class II — residual loss

An allowed action that later creates an adjudicated loss exposure. This drives collateral-backed risk capacity rather than being conflated with policy bypass.

Reproducibility controls

  • Deterministic scenario seeds
  • Canonical JSON serialization
  • Hash-addressed corpus and reports
  • Recorded exact agent configuration
  • Replay mode for stable demonstrations
  • On-chain exam precommitment
Evaluation limitation. The scenario generator and blind material are self-authored under DEC-023. Results are labeled controlled and non-independent; they are useful engineering evidence, not external certification.
07 · Risk-to-authority compiler

Risk estimates become a bounded envelope

The compiler is a pure, versioned function. It uses per-family one-sided Clopper–Pearson bounds, owner-defined threat weights, a risk budget, hard ceilings, usefulness gates and available collateral. All money arithmetic uses integer base units; probability arithmetic is fixed-point bigint.

08 · Qualification protocol

Two keys grant; multiple paths remove

Activation

  1. Examiner calls commitExam(configHash, corpusHash).
  2. Off-chain report and compiler output are finalized.
  3. Examiner signs an EIP-712 attestation.
  4. Owner submits the activation transaction.
  5. Vault validates signature, latest commit, expiry and bond lock.
  6. Qualification becomes active for one agent key.

Signed binding set

qualId · vault · agentKey · configHash · reportHash · corpusHash · examCommitId · ownerInputsHash · t1MaxPerTx · t1MaxPerWindow · t2MaxPerTx · t2Allowed · issuedAt · expiresAt · examiner

Removal and decay

Owner

Immediate revocation or global pause.

Examiner

Revoke a qualification no longer supported by evidence.

BondPool

Suspend atomically when an approved claim pays.

Time

Qualification expires after the recorded validity period.

Grant requires evidence and owner consent. Removal does not require the agent’s cooperation.

EIP-712 domain separation binds signatures to chain ID and verifying contract; attestations are single-use and must reference the latest on-chain exam commit.

10 · Collateral and claims

Residual exposure is mechanically coupled to bond

T1 paymentCreates unreconciled exposure
→
Exposure check≤ remaining locked bond
→
Owner reconcileCloses reviewed exposure

Backing invariant

Unreconciled Tier-1 exposure never exceeds the qualification’s remaining bond.

This stops a compromised agent from bypassing backing simply by generating fresh invoice keys. The vault checks remaining collateral before each T1 payment and updates exposure atomically.

Claim lifecycle

  1. Eligible Tier-1 payment remains unreconciled.
  2. Claim is filed within grace period.
  3. Adjudicator approves or rejects.
  4. Approved payout applies deductible, per-claim cap and remaining-bond cap.
  5. Funds transfer only to the vault.
  6. Qualification is suspended in the same transaction.
Scope boundary. BondPool is a prototype risk-sharing mechanism, not an insurance product. Pricing, premiums, licensing, capital treatment and independent adjudication are outside this submission.

14 · Limitations and roadmap

Evidence with an explicit boundary

Prototype limitations

  • Base Sepolia and MockUSDC, not mainnet assets.
  • Self-assessment; no external smart-contract or AI audit.
  • Controlled, non-independent evaluation.
  • Demo keys are local software keys, not production HSM/MPC custody.
  • Central examiner and adjudicator trust assumptions remain.
  • One-token design and fixed-window accounting.
  • Current live gamma qualification has no T1 authority.

Production path

  1. Independent contract and agentic-security review.
  2. Browser/hardware signing and organizational key policy.
  3. Independent evaluation corpus and model-change governance.
  4. Timelocked administration, monitoring and incident drills.
  5. Legal analysis of custody, payments and risk-sharing structure.
  6. Limited-value pilot with explicit risk acceptance.
Submission thesis. Safe financial autonomy is not a promise that an AI will never fail. It is a system that measures evidence, limits authority, contains failure and makes the result verifiable.
