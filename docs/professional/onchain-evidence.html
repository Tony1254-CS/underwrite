01 · Verification statement

What this dossier proves—and what it does not

Four public testnet transactions establish a coherent path from committed evaluation evidence to a contract-enforced payment. Every asserted successful action has a status-success receipt and a matching decoded event.

Proven

  • Contract bytecode existed at the recorded vault address.
  • The examiner committed the configuration and corpus hashes.
  • The owner activated a qualification for the exact agent key.
  • The agent created pending request 2.
  • The agent later called executePending(2).
  • The receipt succeeded and emitted a matching Tier-2 PaymentExecuted event.

Not claimed

  • No mainnet or real-funds activity.
  • No external audit or certification.
  • No production custody claim.
  • No live Tier-1 authority: the current qualification grants t1=0.
  • No claim that a testnet demonstration predicts operational performance.
Classification: CONTROLLED PUBLIC TESTNET. Token amounts are 6-decimal MockUSDC base units. Private keys never appear in this dossier, repository, or transaction notes.

Verification rule

An action is marked executed only when the RPC receipt reports success and the expected event decodes with matching contract, recipient, amount, invoice key, and tier. The canonical machine-readable companion is evidence/onchain/EVIDENCE_MANIFEST.json.

The model did not choose the address, token, amount limit, or execution tier. Deterministic code and the vault enforced them.

06 · Independent verification guide

Verify without trusting this PDF

The evidence is designed to be checked from public chain data, repository artifacts, and deterministic decoding—not from screenshots.

  1. Open each transaction in a Base Sepolia explorer.
  2. Confirm destination 0x8a1B…D1B0, receipt success, and block number.
  3. Decode the request as requestPayment(address,uint256,bytes32,bytes32).
  4. Decode the execution as executePending(uint256); the argument must be 2.
  5. Decode logs against the published ABI; confirm recipient, amount, invoice key, and tier.
  6. Hash the raw receipt files and compare them with the manifest.
